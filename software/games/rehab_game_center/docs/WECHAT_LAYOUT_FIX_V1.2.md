# 活力公园 V1.2：微信小程序横屏布局修复

本次修复针对“浏览器基本正常、微信小程序横屏人物/长椅/背景明显错位”的问题。

## 根因

1. 背景远景使用 `aspectFill`，中景/前景却使用 `scaleToFill`。在 16:9 附近的 H5 中差异较小，但在 844×390 等更宽的小程序横屏中，中/前景会被横向拉伸，导致分层坐标失配。
2. 人物和长椅同时混用了 `vw`、`vh`、`min-width`、`max-width(px)`。H5 大窗口主要被固定像素上限约束，小程序逻辑像素窗口则主要被 `vh` 约束，因此两端最终比例不同。
3. 微信右上角胶囊按钮会覆盖自定义导航页面的 HUD 右侧区域。
4. 旧事件素材中花坛、风筝、喷泉存在相邻素材/背景残留，放大后会出现矩形贴片感。

## 已修复

- 三个背景层统一使用 `aspectFill`，保证同一裁剪模型。
- 中景/前景重新由同一远景母图生成，去除拼贴接缝。
- 人物与长椅全部改为以 `vh` 为基准的固定比例：跨 H5/微信保持一致，不再使用 `vw + px 上下限` 混合约束。
- 人物和长椅继续共用同一水平中心与底部锚点，站起后长椅保持原位。
- 微信端运行时读取胶囊按钮位置，自动给 HUD 留出右侧安全空间。
- 清理花坛、风筝、喷泉事件素材的明显背景/邻接素材残留。
- 活力公园正式 production 构建增加 debug 门禁；测试构建仍可使用 `debug=1`。
- 新增 `pnpm check:vitality-layout` 静态布局检查。

## 重新测试前必须清缓存

若你之前已经用 HBuilderX 或微信开发者工具打开过旧版本，不要直接覆盖旧目录继续运行。建议：

1. 解压本 ZIP 到一个**新的目录**；
2. 若复制到旧工程，先删除 `dist/`、`unpackage/`；
3. 微信开发者工具中删除旧项目后重新导入，或执行“清缓存 → 全部清除”；
4. 重新执行依赖安装和构建；
5. 控制台运行 `pnpm check:vitality-layout`，看到 `Vitality layout check passed` 后再做视觉验收。

重点尺寸：667×375、844×390、932×430 横屏。
